# Agentic Project Kit v0.4.5

Installable release. v0.4.5 adds one optional manual packaged reasoning skill,
`apk-project-grill`, plus a small release-evidence-ordering correction. Behavior outside these
changes is unchanged, and every previously shipped optional skill keeps its semantics.

## What changed in v0.4.5

- Optional manual packaged skill (plain Markdown shipped in the package, never auto-activated,
  never gating, no new CLI):
  - `apk-project-grill` is a repository-grounded design checkpoint for a whole project, the
    current milestone, or one bounded subsystem/topic (Task 0137). It resolves the requested
    scope, reads canonical project truth with bounded context through existing APK primitives,
    asks one high-value question at a time, and challenges stale or inconsistent assumptions
    while labeling evidence, inference, hypothesis, and human preference. It writes nothing
    before explicit human approval, routes approved decisions to discovered canonical owners
    (never a parallel grill document or session store), and turns approved gaps into follow-up
    tasks with fresh IDs without rewriting completed history. It never modifies product code,
    auto-activates, or becomes a mandatory stage or gate.
- Release-evidence-ordering correction (declarative guidance only, Task 0138): the `release`
  typed template and canonical release docs now require all pre-tag evidence to be observed
  against the exact frozen candidate SHA before tag creation, define post-tag checks separately,
  forbid backfilling post-tag facts into the tagged release-note file, and preserve tag
  immutability.
- Packaging and generated-documentation updates so the installed package ships five portable
  skill assets: `apk-project-grill`, `apk-task-grill`, `apk-task-split`, `apk-prototype`, and
  `apk-milestone-semantic-audit`.

## Compatibility

- Repository-local pinning remains the supported default. No install-time build allowlist is
  needed because `dist/` ships inside the tag.
- Installation does not rewrite existing repositories, customized instructions, or config.
- The optional skills remain manual-only and are not required for ordinary task work.
- Existing `apk-task-grill`, `apk-task-split`, `apk-prototype`, and `apk-milestone-semantic-audit`
  semantics are unchanged.

## Installation

```bash
pnpm add -D git+ssh://git@github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.5
```

HTTPS equivalent:

```bash
pnpm add -D git+https://github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.5
```

`#main` tracks unreleased development; pin a tag for repeatable installs.

## Optional tools, not mandatory stages

`apk-project-grill`, `apk-task-grill`, `apk-task-split`, `apk-prototype`, and
`apk-milestone-semantic-audit` are separate optional tools. A conceptual flow is:

```text
project idea / periodic checkpoint
  -> apk-project-grill
  -> optional task split
  -> optional task grill
  -> normal claim/work/verify/review/gate/done workflow
  -> optional milestone semantic audit
```

None of these steps is mandatory, none is a release or completion gate, and none requires
another.

## Validation

This release is validated before tag creation against the exact frozen candidate: local
`pnpm quality`, `pnpm test:coverage`, `pnpm build`, and `pnpm release:check`; committed-`dist`
currency; contract `lint`/`sync`/`doctor`/`audit`; package payload inspection confirming the five
portable skill assets and working bin aliases; and a representative disposable downstream smoke.

The exact-SHA hosted CI run, the annotated tag object and peeled commit, and the fresh-store cold
install from the published tag are observed after publication and recorded in
`docs/delivery/workflow-v0.4.5-self-dogfood.md`. This file deliberately does not assert
post-publication facts, and a release-note file committed inside the tag cannot contain its own
commit SHA or the later tag/CI/install identity.
