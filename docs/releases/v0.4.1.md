# Agentic Project Kit v0.4.1

Patch release for downstream Codex/OpenCode dogfood. It contains the adoption fixes and the medium-risk assurance/review correction that landed after v0.4.0.

## Fixes since v0.4.0

- `apk adopt` now emits a canonical `AGENTS.md` that exactly matches the exporter, so `apk lint` and `apk sync` are current immediately after adoption (Task 0106).
- `apk adopt` selects a collision-free follow-up task id. It reuses an existing adoption task on re-runs and otherwise picks the next free numeric id after the repository's tasks, so adopting a repository that already contains task `0001` no longer creates a duplicate id (Task 0107).
- Legacy `independentReview`/`reviewLevel` policy fields are now a coherent projection of canonical assurance (Task 0108):
  - low = `none`, medium = `self-check`: no separate semantic reviewer, and ordinary medium tasks no longer block completion on a review record or consume constrained scarce-frontier review capacity;
  - high = `fresh-context`: a separate isolated reviewer at the lightweight level;
  - critical = `independent`, with `diverse` preferred when policy raises it;
  - security/auth and release/integration escalation still raise to independent; migration, async/worker, public API, large semantic diffs, weak tests, invariant changes, uncertainty, unexpected scope, and repeated deterministic failures still raise to fresh-context;
  - calibration remains raise-only and can never lower canonical assurance or create a review lane for a self-check task.

## Compatibility

- Legacy v0.3.1 repositories remain adoptable.
- Configs with absent `schemaVersion` or `schemaVersion: 1` migrate only through explicit `apk adopt --apply` to `schemaVersion: 2`.
- Customized `AGENTS.md` files are never silently overwritten. Old generated Codex/OpenCode/Cursor policy duplicates can be reported, and exact generated copies can be cleaned safely.

## Pinning

Repository-local dependency pinning is preferred over a global install for reproducibility. Install the stable tag into a repository:

```bash
pnpm add -D git+ssh://git@github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.1
```

HTTPS equivalent:

```bash
pnpm add -D git+https://github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.1
```

`#main` tracks unreleased development and is for testing only. Do not use it as the stable installation path.

## Intended dogfood workflow

- APK is the repository control plane.
- Codex and OpenCode are used normally from VS Code.
- Codex and OpenCode read the canonical `AGENTS.md`; no redundant common-policy files are required.
- APK does not need to launch or supervise Codex or OpenCode.

## Runtime boundary

External terminal/session runtimes can be used alongside APK. No Herdr dependency, adapter, PTY, SSH, process supervisor, scheduler, or runtime orchestration is included. The runtime-neutral and workspace abstractions remain available and are not required for this workflow.

## Validation

The release is validated by green exact-SHA hosted CI for the tagged commit and a disposable brownfield adoption smoke test run from the tag.
