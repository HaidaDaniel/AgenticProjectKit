# Agentic Project Kit v0.4.6

Installable patch release. v0.4.6 adds a developer-local human communication language preference,
strengthens optional grill decision context, and adds a non-failing advisory for explicitly
configured `agentStyle: caveman`. Behavior outside these changes is unchanged, and every
previously shipped optional skill keeps its semantics.

## What changed in v0.4.6

- Developer-local human communication language preference (Task 0141). A developer can persist a
  preferred human-facing interaction language locally with `apk language set <tag>` (`apk language
  show`, `apk language reset`). The preference is stored outside the repository
  (`$XDG_CONFIG_HOME`/`~/.config`, macOS Application Support, or Windows
  APPDATA/LOCALAPPDATA, with `APK_LOCAL_CONFIG_HOME` as an explicit override) and is never
  Git-tracked. Resolution precedence is an explicit current-invocation/session override
  (`apk prompt --language <tag>` or `APK_COMMUNICATION_LANGUAGE`), then the persisted local
  preference, then English. An explicit override never persists itself. The resolved language is
  carried through APK-owned guidance (`apk prompt` and the `apk-project-grill`/`apk-task-grill`
  assets) while identifiers, paths, commands, config keys, quoted facts, machine-readable output,
  and tracked repository artifacts stay canonical English. APK does not control an external
  harness's chat runtime and does not promise to translate its output. This is not whole-product
  i18n/localization, and `.agentic/config.json` gains no language key.
- Grill decision-context preservation (Task 0142). Both optional grill assets (`apk-project-grill`,
  `apk-task-grill`) now require compact decision context before each non-trivial question:
  established repository facts, the remaining material ambiguity, and how the answer changes the
  decision/contract downstream. Terse and specialty styles (`caveman` or other compression) may
  shorten wording but must not suppress that context. One-question-at-a-time cadence, manual-only
  activation, approval-before-write, and skill-local scope are unchanged.
- Explicit-caveman advisory (Task 0143). `apk doctor` now emits one non-failing `warn` when
  `.agentic/config.json` explicitly sets `agentStyle: caveman`, explaining that current APK
  defaults omitted/new `agentStyle` to `normal` and that the explicit value is preserved
  intentionally, and that removing the setting or setting `agentStyle` to `normal` restores normal
  communication. The advisory never rewrites config, never labels the value legacy/deprecated, and
  never turns an otherwise passing flow into failure. No `apk upgrade` command or migration engine
  is added.
- Historical release-evidence correction (Task 0140). The v0.4.5 release-evidence chronology is
  clarified in repository documentation without rewriting the published `v0.4.5` tag. This is a
  historical documentation correction already present since v0.4.5, not a new user-facing feature.

## Compatibility

- Repository-local pinning remains the supported default; `dist/` ships inside the tag, so no
  install-time build allowlist is needed.
- English remains the deterministic fallback and the canonical language of tracked repository
  artifacts. Installing or upgrading to v0.4.6 changes no existing repository file.
- Existing `.agentic/config.json` files require no migration. Explicit `agentStyle` values are
  preserved; the advisory is informational only.
- The optional skills remain manual-only and are not required for ordinary task work. Existing
  `apk-project-grill`, `apk-task-grill`, `apk-task-split`, `apk-prototype`, and
  `apk-milestone-semantic-audit` semantics are otherwise unchanged.

## Upgrade notes

- This is a patch release with no breaking changes. Pin `#v0.4.6` to pick it up.
- To adopt a human communication language, run `apk language set ru` (or another short language
  tag). Two developers using the same repository can choose different languages with no Git diff.
- If a project deliberately kept `agentStyle: caveman`, `apk doctor` will now show a one-line
  advisory. Remove the setting or set `agentStyle` to `normal` to return to normal communication;
  leaving it as-is keeps the intentional caveman behavior.

## Installation

```bash
pnpm add -D git+ssh://git@github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.6
```

HTTPS equivalent:

```bash
pnpm add -D git+https://github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.6
```

`#main` tracks unreleased development; pin a tag for repeatable installs.

## Optional tools, not mandatory stages

`apk-project-grill`, `apk-task-grill`, `apk-task-split`, `apk-prototype`, and
`apk-milestone-semantic-audit` are separate optional tools. None is mandatory, none is a release or
completion gate, and none requires another.

## Validation

This release is validated before tag creation against the exact frozen candidate: local
`pnpm quality`, `pnpm test:coverage`, `pnpm build`, and `pnpm release:check`; committed-`dist`
currency; contract `lint`/`sync`/`doctor`/`audit`; package payload inspection confirming the five
portable skill assets and working bin aliases; focused v0.4.6 regressions for the communication
language preference, grill decision context, and caveman advisory; and a representative disposable
downstream smoke.

The exact-SHA hosted CI runs against the frozen candidate and must conclude `success` before the
annotated tag is created, so that CI is pre-tag evidence. The frozen candidate SHA/tree, that
hosted CI run, the annotated tag object and peeled commit, and the fresh-store cold install from
the published tag are recorded after publication in
`docs/delivery/workflow-v0.4.6-self-dogfood.md`. This release-note file deliberately does not
assert post-publication identities or results, and a file committed inside the tag cannot contain
its own commit SHA or the later tag/CI/install identity.
