# Agentic Project Kit v0.4.2

Installable release. v0.4.2 keeps the policy and adoption fixes from v0.4.1 and fixes the Git-tag packaging so downstream repositories can install the CLI without configuring a build-script allowlist.

## Why v0.4.2 exists

v0.4.1 contained the Task 0106/0107 adoption fixes and the Task 0108 assurance/review correction, but it was not installable from its Git tag with pnpm 10:

```text
ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED
The git-hosted package "agentic-project-kit@0.4.1" needs to execute build scripts
but is not in the "onlyBuiltDependencies" allowlist.
```

A Git install fetched the source and tried to build it through the package `prepare` lifecycle, which pnpm blocks for git dependencies. v0.4.1 is preserved as history and is not moved or retagged.

## What changed in v0.4.2

- The built `dist/` is committed and ships inside the Git tag, so the tag contains a runnable package.
- The install-time `prepare` script is removed. There is no `prepare`, `postinstall`, or `install` build hook. Husky is developer tooling only and is installed with `pnpm setup:dev`.
- CI builds and rejects a stale committed `dist/`, so source and shipped artifact cannot drift.
- A fresh-store install acceptance test verifies a brand-new empty pnpm store can install the tag with no `onlyBuiltDependencies`/`allowBuilds` configuration.

Source behavior is unchanged from v0.4.1.

## Included fixes

- `apk adopt` emits a canonical `AGENTS.md` that exactly matches the exporter, so `apk lint` and `apk sync` are current immediately after adoption (Task 0106).
- `apk adopt` selects a collision-free follow-up task id (Task 0107).
- Legacy `independentReview`/`reviewLevel` fields are a coherent projection of canonical assurance (Task 0108): low = `none`, medium = `self-check` (no separate reviewer), high = `fresh-context`, critical = `independent`, with security/auth and release/integration still escalating to independent and calibration raise-only.

## Installation

Repository-local dependency pinning is preferred over a global install for reproducibility. No build-script allowlist is required:

```bash
pnpm add -D git+ssh://git@github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.2
```

HTTPS equivalent:

```bash
pnpm add -D git+https://github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.2
```

`#main` tracks unreleased development and is for testing only. Do not use it as the stable installation path.

v0.4.1 and earlier Git tags build on install and may require `onlyBuiltDependencies`/`allowBuilds`; prefer v0.4.2 or newer for a self-contained tag.

## Intended dogfood workflow

- APK is the repository control plane.
- Codex and OpenCode are used normally from VS Code and read the canonical `AGENTS.md`; no redundant Codex/OpenCode common-policy files are required.
- APK does not need to launch or supervise Codex or OpenCode.
- External terminal/session runtimes are optional and deferred. No Herdr dependency, adapter, PTY, SSH, process supervisor, scheduler, or runtime orchestration is included.

## Validation

The release is validated by green exact-SHA hosted CI for the tagged commit, a fresh-store install from `#v0.4.2` with no allowlist, and a disposable brownfield adoption smoke test run from the tag.
