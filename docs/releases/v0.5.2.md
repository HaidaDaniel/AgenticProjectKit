# Agentic Project Kit v0.5.2

Pre-tag patch candidate for corrective work after v0.5.1. This note contains
facts known before publication. The latest validated installable release remains
v0.5.1 until the frozen candidate passes release checks and actual-tag validation.

## Changes

- Status and attention select actionable doing/review/blocked tasks before todo,
  report omitted or incomplete diagnostics, and retain healthy parsed tasks when
  another contract is malformed or unreadable.
- Workers use a separate lightweight registry/session/task projection. They do
  not invoke status, completion gates, provenance, evidence journals or run logs.
  Duplicate active/archive task IDs make session bindings unknown; incomplete or
  unreadable canonical inventories cannot produce false readiness.
- Status detail and attention share one read-only diagnostic snapshot per call.
  Task files and shared journals are read once; gates and provenance reuse those
  inputs. Repository/task/baseline/candidate/worktree bindings and bounded input
  witnesses reject mixed concurrent results. Each new invocation reads fresh state.
- Pending or stale independent review and changes_requested remain agent work.
  Attention requests an operator for proven budget or explicit approval conditions;
  unavailable assurance or session data alone does not imply human intervention.
- All three CLI aliases support --version from the installed APK manifest,
  including source/packaged entrypoints, foreign host manifests and use outside Git.
- Doctor recognizes Python application/build evidence and reports installation or
  launcher inconsistencies without adding Node dependencies to downstream projects.
- Archive preview/apply refuses Git-ignored destinations that would remove task
  files from subsequent Git snapshots. Read-only compatibility and operational-file
  diagnostics expose legacy task contracts and already-tracked runtime artifacts.
- Canonical session-directory failures remain unknown rather than silently skipped.
  Generated long task goals and review/failure handoffs use marked bounded summaries
  while retaining complete contracts/evidence and strict external package parsing.
- External verification uses current task attribution and recaptures identity and
  ownership before accepting evidence; contract-mutation races fail closed.

Tasks 0227–0241 provide these corrective changes and the bounded handoff research.
Task 0237 records the portability limitation and an untrusted export/inspection
proposal; this release does not implement trusted evidence import or provenance
recovery. Historical Task 0221 remains blocked. Planned Task 0223 remains separate.

## Compatibility and limits

The package requires Node.js >=22.22.1. Release validation targets Node.js 22.22.1,
pnpm 10.28.1 and the Ubuntu hosted runner. Other runtimes/platforms are not a tested
matrix. No dependencies are added, and existing CLI/JSON fields are retained.

Snapshot reuse reduces repeated content reads and adds bounded metadata/Git checks.
Operation counts are not a promise of lower wall time for every repository. The
witness is an optimistic consistency check, not a filesystem transaction. Unknown
or over-limit inputs fail closed. Ignored local agent/evidence/session records are
not transported by ordinary Git clone/pull; disposable-clone tests state that limit.
