# Agentic Project Kit v0.4.7

Installable correctness patch release. v0.4.7 consolidates the task-workflow correctness foundation delivered by Tasks 0145-0148. It retains the AgenticProjectKit product identity, all existing CLI names, and the previously shipped behavior outside these fixes.

## What changed in v0.4.7

- Task 0145 preserves multiline task-list content through parse/render/write operations and fails closed when task Markdown contains unsupported structures that could be silently lost.
- Task 0146 makes declared benchmark verification evidence satisfiable through local and external verification records while keeping evidence bound to the declared check and current candidate.
- Task 0147 keeps a declared manual artifact reference distinct from the observer-supplied evidence reference and requires coherent, current candidate evidence at the gate.
- Task 0148 attributes legitimate unrelated intervening commits only when canonical task provenance and Git lineage prove ownership and unrelatedness. Anonymous, overlapping, unsupported, dirty, or stale-HEAD cases continue to fail closed. Git path attribution preserves pathnames losslessly or rejects unsupported names.

## Compatibility

- This is a patch release with no dependency changes or intended CLI renames. `apkit`, `apk`, and `agentic-project-kit` remain package command aliases for the same CLI entrypoint.
- Repository-local pinning remains the supported default. The published tag includes committed `dist/`, so installation does not require a build-script allowlist.
- Existing valid task contracts and previously shipped optional tools retain their behavior. Task Markdown structures APK cannot safely preserve now receive a fail-closed diagnostic; repair those task files before relying on parse/render/write operations.
- Tasks 0149 and 0150 remain deferred product-identity work. This release makes no rebrand decision and does not include unfinished public-readiness implementation.

## Upgrade notes

- Pin `#v0.4.7` for repeatable installs. No dependency migration is required.
- If a task contract uses an unsupported Markdown structure, `apk lint` or task parsing may now reject it instead of silently rewriting content. Resolve the diagnostic while preserving the original task intent.
- Benchmark checks and manual artifact checks should declare their structured evidence requirements; verification records must refer to the current candidate and the exact declared check/artifact.

## Validation

The frozen release candidate is validated before tag creation with typecheck, lint, the full test suite, coverage, build, release checks, APK contract lint/sync/audit/doctor, committed-`dist` currency, version and package-payload inspection, and `git diff --check`. GitHub Actions Quality must complete successfully for the exact frozen candidate SHA before the annotated tag is created.

The release candidate SHA/tree, exact-SHA CI identity, annotated tag object and peeled commit, actual-tag cold install, and downstream smoke are recorded separately in `docs/delivery/workflow-v0.4.7-self-dogfood.md` after publication. This release note contains no post-tag identity or results.
