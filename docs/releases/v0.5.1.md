# Agentic Project Kit v0.5.1

Pre-tag patch release candidate for repository workflow correctness. This note
records facts known before publication. The validated installable release remains
v0.5.0 until exact-candidate checks, publication, and actual-tag validation finish.

## Changes

- Task candidate identity preserves current verification across lifecycle-only
  bookkeeping commits while material content, file modes, symlink targets, staged
  divergence, and submodule revisions remain identity-bearing or fail closed.
- Verification diagnostics distinguish nonzero exits, timeout, signal, spawn
  failure, and unknown termination without inferring timeout from a signal alone.
- Task creation and static lint reject interior dot segments and repeated leading
  `./` prefixes. Exactly one leading `./` remains a compatible path alias.
- Audited contract amendments retain exact operator preview approval and append-only
  epochs. Bounded historical epoch recovery preserves original journal bytes while
  rejecting changed identities, hashes, carried paths, invalid timestamps, and
  foreign-task chains. Modern records use one strict writer/reader identity encoder.
- The workspace freshness regression now distinguishes a new Git revision from
  changed task candidate content.

Tasks 0217, 0219, 0220, 0222, and 0224 supply the completed correction work. Task 0221
retains its blocked historical attribution state; this release does not retroactively
certify that candidate. The remaining epoch repair was independently verified under
Task 0224 on a fresh baseline. No emergency branch is merged wholesale.

## Compatibility

The package requires Node.js `>=22.22.1`; the release validation target is Node.js
`22.22.1`, pnpm `10.28.1`, and the Ubuntu hosted runner. The `apkit`, `apk`, and
`agentic-project-kit` aliases use the same committed CLI. No dependencies are added.
The v0.5.0 tag and historical evidence remain immutable.

Task 0223 remains planned after this patch: its opt-in exact-push CI parity command
requires a separate configuration, worktree/process implementation, failure matrix,
and timing validation. Tasks 0216 and 0218 remain research work. None is a mandatory
prerequisite of this patch release.

new reproducible installation target.

## Validation chronology

Before tagging, freeze one committed candidate and run the full `pnpm release:check`
in a clean checkout with the pinned toolchain. Confirm committed dist, package and
lockfile, packed payload, CLI smoke, and hosted GitHub Actions success on that exact
SHA. Create the annotated tag only after those pre-tag checks pass.

Actual-tag cold installation, tag object and peel, installed version, alias and
downstream CLI smoke, and the unchanged v0.5.0 identities are post-tag evidence.
Record them in a separate delivery artifact and promote stable documentation only
after validation. Never backfill those later identities into this tagged note.
