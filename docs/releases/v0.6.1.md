# Agentic Project Kit v0.6.1

Status: pre-tag release candidate.

This patch candidate consolidates the corrective milestone delivered after v0.6.0 by Tasks
0286-0305. It introduces no new product feature line; every behavioral change narrows an
existing write boundary, corrects a diagnostic or lifecycle verdict, or improves the workflow
around routine agent use.

## Security and filesystem containment

Generated writes are now fail-closed at every audited boundary. `sync` and `export` refuse a
symlink final component, a symlinked ancestor, or an escaping path before writing
(Task 0286). `init` starter files and the additive `.gitignore` writer apply the same
containment (0287). Legacy export cleanup preflights the whole generated deletion set and
refuses symlinks, escaping paths, and classification-to-delete races before the first removal
(0290). Audit report and project-map writes are preflighted as one batch and refuse the same
conditions (0291). Task 0300 adds a readable per-call-site mutation matrix and a durable
guard against new uncontained mutation paths.

## Doctor diagnostics

`doctor` now reports canonical operational ignore entries missing from `.gitignore`
(0288) and determines effective ignore status independently per entry instead of inferring
from one probe per family (0292). The corrected diagnostic also fixes a false pass previously
certified by the downstream dogfood record. All doctor checks stay read-only and show a safe
fix path without modifying files.

## Task lifecycle, attention, and operator escalation

Attention actions are derived from task lifecycle state rather than blocker strings, so a
recommended action is one the CLI accepts (0293). A blocked task with an exhausted review
budget or another operator-only condition reports `needsHuman: true` with an executable
operator decision action, while blocked tasks without such conditions keep their
lifecycle-derived actions (0303, 0305). Task contracts may declare read-only external
evidence references without being mistaken for missing repository-relative context files
(0295).

## Assurance, security oracle, and release reproducibility

Safety-critical verdict changes - diagnostics, containment authorization, provenance, and
security decisions - now require independent assurance without a special case for any single
task (0294). Task 0301 adds an independent security-verdict regression suite whose negative
controls were corrected so the oracle cannot pass by reusing the implementation's faulty
assumptions. Task 0302 makes the documentation tree resolvable from tracked files only and
proves `pnpm release:check` succeeds from a genuinely clean checkout, so untracked local files
can no longer satisfy a release link. Task 0304 removes the cross-test global filesystem
monkeypatch that made the configuration-change diagnostic snapshot intermittent.

## Worker, context, performance, and CLI

`status --detail` and `attention --json` avoid repeated task-inventory work under a guarded,
read-only snapshot (0296; see the wall-clock measurements recorded with that task). Task
context requests can select bounded document sections instead of whole large policy files
(0297). Runtime dependencies are limited to packages actually used at runtime while build and
test tooling remain available in development (0298). Task and status projections gain machine
-readable JSON output and a self-contained `help` alias (0299).

## Compatibility and migration

Existing task, backlog, provenance, generated-instruction, and CLI behavior is preserved.
New ignore diagnostics are advisory and read-only: a repository missing canonical entries
continues to work and gains a report rather than an automatic edit. Attention JSON gains
structured operator-condition information without changing successful field shapes.
Installations pinned to v0.6.0 need no configuration change to keep working; adopting this
version later is a normal tag repin after validation. No migration, data rewrite, or new
runtime dependency is introduced.

## Known limitations

- Pre-mutation TOCTOU remains a documented boundary: containment checks run immediately
  before each write, but an adversarial local actor that swaps a path between check and write
  is not fully prevented.
- Cross-host worker lock ownership is conservatively classified as uncertain, and Windows
  symlink privilege behavior is untested.
- A previously observed diagnostic snapshot flake appeared once under c8 instrumentation and
  was corrected in 0304; the canonical full suite is the authority for this candidate.
- The measured status/attention improvements are operation-count and wall-clock observations
  on the recorded fixtures, not a universal timing guarantee.
