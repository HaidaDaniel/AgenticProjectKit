# Agentic Project Kit v0.4.8

Pre-tag public-readiness release candidate. This note records the intended scope and
compatibility facts known before publication; it does not claim that a `v0.4.8` tag has
been published or post-tag validated.

## What changed in v0.4.8

- Task 0170 publishes a truthful security policy that directs reporters to GitHub Private
  Vulnerability Reporting, discourages public disclosure of exploit details, and makes no
  separate email, SLA, bounty, or response/fix deadline claim.
- The public README and documentation home link to the security policy without duplicating
  its handling guidance.

## Compatibility

- This is a patch release candidate with no dependency changes or intended CLI renames.
  `apkit`, `apk`, and `agentic-project-kit` remain package command aliases for the same
  CLI entrypoint.
- The current validated installable release remains `v0.4.7` until this candidate passes
  exact-candidate, hosted-CI, immutable-tag, and post-tag validation.
- Tasks 0149 and 0150 remain deferred product-identity work. This candidate makes no
  rebrand decision and does not require or imply naming work.

## Installation

Continue to use the validated tag until publication and post-tag validation complete:

```bash
pnpm add -D agentic-project-kit@git+https://github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.7
```

If the release is published and post-tag validation succeeds, the exact `v0.4.8` tag
will be the reproducible installation target.

## Validation chronology

The release process must run the declared PRE-TAG checks against one frozen candidate SHA,
including exact-SHA hosted Quality, before creating an annotated tag. Actual-tag cold
installation, released package identity, downstream installation, and post-release
self-adoption are separate POST-TAG checks and belong in a separate delivery artifact.
