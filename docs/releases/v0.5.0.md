# Agentic Project Kit v0.5.0

Pre-tag corrective performance-observability release candidate. This note records facts known
before publication; it does not claim that a `v0.5.0` tag has been published or post-tag
validated. The immutable `v0.4.9` release remains the first profiler generation and remains
unchanged.

## What changes in v0.5.0

- The profiler writes trace/report schemaVersion 2 and distinguishes the reconstructed full
  Node process lifetime, the instrumented invocation boundary, startup/import residual, APK
  internal time, subprocess intervals, and the rewrite-sensitive APK runtime share.
- Valid schemaVersion 1 traces remain readable where possible. Their missing full-process and
  startup measurements are reported as unavailable; v0.5.0 does not fabricate a rewrite ceiling
  from v1 data.
- Primary command-kind attribution is disjoint and includes test, lint, typecheck, build,
  coverage, package-manager, Git, repository-tool, and other observed subprocess kinds. Child
  duration sum remains separate from child wall-clock union.
- The benchmark harness pairs identical profiling OFF/ON workloads, measures parent
  spawn-to-exit separately from Node-observed process lifetime, covers short commands and
  verification-heavy test/lint/typecheck/build work, and records bounded repetition statistics.
- `apk perf exec --category typecheck -- ...` is available for controlled repository-tool
  measurement. Profiling remains local, opt-in, privacy-preserving, and off by default.

The committed [v0.5.0 self-dogfood baseline](../benchmarks/apk-performance-v050-self-baseline.md)
is development evidence for attribution, not a universal Go conclusion. Final Node-versus-Go
analysis requires real downstream workflows using the released v0.5.0 package.

## Compatibility and support

- This is a minor release candidate. `apkit`, `apk`, and `agentic-project-kit` remain aliases
  for the same CLI entrypoint.
- Normal APK workflows do not require profiling, a benchmark step, a daemon, a database, a
  network service, or an LLM. LLM generation, model/API waiting, reasoning, user think time,
  and idle/unobserved gaps remain excluded.
- Trace data stays under local `.agentic/perf/` storage and is not task provenance, candidate
  hashing, package payload, or telemetry. Raw argv, environment values, stdout/stderr,
  prompts, responses, file contents, and secrets are not stored.
- The current validated installable release remains `v0.4.9` until this candidate passes
  exact-candidate, hosted-CI, immutable-tag, and post-tag validation. No N-1 support promise,
  SLA, response deadline, bounty, or fixed maintenance window is introduced.
- Tasks 0149 and 0150 remain deferred product-identity work. This release makes no rebrand
  decision.

## Installation

Continue to use the validated tag until publication and post-tag validation complete:

```bash
pnpm add -D agentic-project-kit@git+https://github.com/HaidaDaniel/AgenticProjectKit.git#v0.4.9
```

If publication and post-tag validation succeed, the exact `v0.5.0` tag will become the
reproducible installation target.

## Validation chronology

The release process must run the declared PRE-TAG checks against one frozen candidate SHA,
including exact-SHA hosted Quality, before creating an annotated tag. Actual-tag cold
installation, released package/bin identity, v2 profiler smoke, v1 compatibility smoke,
downstream installation, and post-release self-adoption are separate POST-TAG checks and belong
in a separate delivery artifact. This note must not be backfilled with those later identities or
results.
